# 这个 EasyEDA Skill 还需要改什么

更新日期：2026-08-16

## 先说结论

最主要的问题已经修了：现在不会再为每一条线临时写一个新脚本，也已经有步骤
耗时记录、PCB 边界检查、统一操作工具和备份验证工具。时间现已改成“只记录和
提示，不因耗时停止”。

下一次拿真实 PCB 测试之前，最值得先完成下面三件事：

1. 让电脑实际使用仓库里的最新版；
2. 做一次接近真实任务的完整演练；
3. 每完成一个可接受阶段，马上建立真正可恢复的备份。

这份清单只讨论本仓库里的 Skill，不修改其他工作区，也不处理那块 ESP32-C3
PCB 本身。

## 必须先做

### 1. 安装仓库里的最新版

**现在的问题**

仓库里的 Skill 已经更新，但电脑当前安装的仍是旧版本。也就是说，下次开始新任务
时，Agent 可能仍按照旧规则工作，看不到这次新加的工具和保护措施。

**要怎么改**

重新安装当前仓库中的整个 `skills/easyeda-pcb-design/` 文件夹。不能只复制入口
文件，也不能把仓库的测试文件和设计文件一起装进去。

**怎样算完成**

新开一个任务后，Agent 能识别最新版的统一操作工具、步骤耗时记录、PCB 边界检查和
备份恢复规则。

## 本次已经完成

### 时间只用于记录和分析，不用于强制停止

**现在的问题**

旧实现会在总时间、某个阶段时间或“长时间没有完成阶段目标”达到上限后自动停止。
现在已经删除这些时间停止条件。

**现在的行为**

保留每一步的时间记录，包括：

- 步骤名称；
- 开始时间和结束时间；
- 本步骤耗时；
- 尝试次数；
- 得到了什么结果；
- 是否让设计向前推进；
- 如果没有推进，卡在哪里。

同时汇总整个任务、各设计阶段和重复尝试的总耗时。耗时异常时可以提醒用户，说明
“这一方向已经用了多久、做了几次、仍卡在哪”，但不能仅仅因为时间到了就禁止继续。

真正需要停止的情况仍然保留，例如：缺少用户必须作出的产品决定、没有可靠备份、
工程或 PCB 身份不匹配、修改结果无法确认、继续操作可能破坏现有设计。它们是安全
或证据问题，不是时间问题。

**验证结果**

用测试证明：无论单步或整个任务耗时多长，系统都能准确输出时间报告，但不会返回
“因为超时而禁止执行”。另一块 PCB 的旧记录、错误版本或缺少备份仍然会因为证据
不匹配而被拒绝。

## 仍需完成

### 2. 做一次接近真实情况的演练

**现在的问题**

现有自动测试能证明各个工具单独可用，但还没有完整验证 Agent 面对一块“已经布了
一部分线、证据又不完整”的真实 PCB 时，会不会正确停止，而不是继续修改。

**要怎么改**

增加一个只读演练，不接触真实 PCB。告诉一个全新会话：继续一块未完成的生产 PCB，
但故意缺少有效备份或最新布局检查。

Agent 应该指出缺少什么、拒绝直接写入，并给出唯一的下一步；不应该临时再写几十个
脚本，也不应该从头重建设计。

**怎样算完成**

全新会话在没有看到标准答案的情况下，能稳定作出上述判断并通过记录的基线测试。

### 3. 每个成功阶段都建立可恢复备份

**现在的问题**

目前已经能检查 EasyEDA 原生 `.epro` 备份是否匹配，也能在测试工程中验证恢复。
但一次布线修改验收通过后，系统还没有把“立刻为这个新版本建立下一份备份”变成
强制步骤。

**要怎么改**

每次接受一个新的 PCB 状态后，先暂停后续修改，依次完成：

1. 保存并重新打开 PCB；
2. 导出新的 `.epro`；
3. 记录文件校验值和当前 PCB 版本；
4. 在单独的测试工程中恢复一次；
5. 恢复结果完全一致后，才允许继续下一次生产 PCB 修改。

**怎样算完成**

旧备份不能用于新版本；没有新备份或恢复测试失败时，系统会停止并明确要求先补备份。

## 做完上面三项后再完善

### 4. 生成一页“当前做到哪里”的总览

现在的检查结果分散在多个文件里。可以增加一份总览，直接告诉人：需求、原理图、
布局、布线、铜皮、DRC、备份和生产文件分别是“当前有效”“已经过期”“缺少”还是
“本项目不需要”。

这样就不会因为某一项检查通过，误以为整块 PCB 都已经完成。

### 5. 用旧任务验证新版工具确实能替代旧脚本

只读扫描旧任务中的脚本，确认每一种修改操作在新版中都有明确处理方式。然后分别用
一份布线、修复、元件移动、板框和铜皮样例，在测试工程中比较新旧结果。

旧任务文件只作为历史证据，不能修改，也不能冒充当前 PCB 的最新证明。

### 6. 明确三种高风险操作是否支持

下面三种操作影响范围较大：

- 整体更新网表；
- 批量导入原理图变化；
- 自动布线。

每一种都要二选一：要么补齐专用的备份、授权、执行和复查流程；要么明确写成“不支持，
必须停止”。不能再为它们临时创建一次性脚本。

### 7. 增加一个统一的仓库检查命令

把现在分散的格式检查、工具测试、链接检查和回归测试串成一个仓库级命令。以后每次
修改 Skill 后运行一次，就能知道是否破坏了原有规则。

## 建议顺序

先安装最新版，然后做真实场景演练，并补上每阶段备份。这三项完成后，才继续制作
状态总览、验证旧任务兼容性和处理高风险操作。

即使所有项目都完成，也只代表 Skill 的工作流程更可靠，不代表任何具体 PCB 已经可以
生产或下单。具体 PCB 仍要单独检查原理图、布局、布线、DRC 和生产文件。
